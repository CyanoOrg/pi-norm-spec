# v0.2 Rust-backed Adapter Execution Plan

Goal: replace the duplicated TypeScript semantics with a Rust-backed pi adapter
while retaining a minimal, typed ExtensionAPI entry point.

## Gate A — Bootstrap

- [x] Establish repository governance.
- [x] Record the hybrid adapter and upstream-authority decisions.
- [x] Define Rust engine and bridge crates.
- [x] Add the TypeScript extension entry skeleton.
- [x] Add protocol fixtures and CI gates.

## Gate B — Upstream contract

- [ ] Pin a norm-spec Rust version and supported machine protocols.
- [ ] Reject incompatible protocol versions with a stable error.
- [ ] Exercise shared fixtures without skip-on-error behavior.

## Gate C — Runtime bridge

- [ ] Measure short-lived versus persistent bridge latency and packaging.
- [ ] Record the chosen process/binding model.
- [ ] Implement JSON/JSONL framing, IDs, cancellation, and graceful shutdown.
- [ ] Surface startup and crash failures to the extension.

## Gate D — pi behavior

- [ ] Implement per-turn path-scoped convention collection.
- [ ] Inject structured summaries without persisting them in session history.
- [ ] Enforce single-operation rules at `tool_call` time.
- [ ] Provide explicit and tested escape behavior.
- [ ] Surface post-edit validation as soft feedback.

## Gate E — Distribution and release

- [ ] Build Linux, macOS, and Windows bridge artifacts.
- [ ] Bundle or reliably resolve the correct platform binary.
- [ ] Run real pi install, injection, and blocking tests.
- [ ] Complete release-quality and security review.
- [ ] Release `v0.2.0` from `main`.

## Human checkpoints

Upstream version pinning, process model, escape semantics, public alpha, and
stable publication require maintainer approval.
