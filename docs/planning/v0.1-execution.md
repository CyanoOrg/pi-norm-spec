# v0.1 Initial Rust-backed Adapter Execution Plan

Goal: ship a self-contained Rust-backed pi adapter with a minimal, typed
ExtensionAPI entry point and no duplicated `.norm` format semantics.

## Gate A — Bootstrap

- [x] Establish repository governance.
- [x] Record the hybrid adapter and upstream-authority decisions.
- [x] Define Rust engine and bridge crates.
- [x] Add the TypeScript extension entry skeleton.
- [x] Add protocol fixtures and CI gates.
- [x] Establish the independent public `0.1` product line.

## Gate B — Upstream contract

- [x] Select the norm-spec CLI machine boundary and pin the initial public
      product plus exact compatibility identities (D005).
- [x] Define a release-derived, platform-specific payload that includes the
      complete conformance inputs and has no implicit `PATH` fallback (D006).
- [x] Resolve the matching payload for norm-spec `0.1.0-rc.1` and verify its
      checksum, manifest source revision, and declared identities.
- [x] Reject incompatible protocol versions with a stable error.
- [x] Consume compatibility, collect, and validate machine responses without a
      parser, filesystem-walk, or empty-ruleset fallback.
- [x] Exercise all 82 cases from the exact upstream contract bundle without
      skip-on-error behavior.
- [x] Confirm the same payload/identity/conformance path on all four native
      hosted targets for the exact Gate B candidate.

## Gate C — Runtime bridge

- [x] Measure short-lived versus persistent pi bridge latency, cancellation,
      crash isolation, and packaging while keeping the D005 upstream CLI
      boundary fixed.
- [x] Record the chosen pi bridge lifecycle model (D008).
- [ ] Implement JSON/JSONL framing, IDs, cancellation, and graceful shutdown.
- [ ] Surface startup and crash failures to the extension.

## Gate D — pi behavior

- [ ] Implement per-turn path-scoped convention collection.
- [ ] Inject structured summaries without persisting them in session history.
- [ ] Add the single pi-specific Skill and one-notice zero-`.norm` onboarding
      path from D007 without automatic project writes.
- [ ] Complete a functional Alpha checkpoint with real install, handshake,
      collection, cold-start, and ephemeral-injection evidence.
- [ ] Record the exact machine-evaluable enforcement subset; natural-language
      conventions remain prompt guidance unless a typed evaluator owns them.
- [ ] Enforce that declared subset at `tool_call` time.
- [ ] Provide explicit and tested escape behavior.
- [ ] Surface post-edit validation as soft feedback.

## Gate E — Distribution and release

- [ ] Build Linux, macOS, and Windows bridge artifacts for every supported
      upstream target.
- [ ] Publish platform-specific optional packages containing the bridge and
      verified upstream runtime/conformance payload.
- [ ] Register only the pi-specific Skill; retain upstream canonical files only
      as non-surfaced provenance when present in the vendor payload.
- [ ] Run real pi install, injection, and blocking tests.
- [ ] Complete release-quality and security review.
- [ ] Release `v0.1.0` from `main`.

## Human checkpoints

Upstream version pinning, process model, escape semantics, public alpha, and
stable publication require maintainer approval.
